# v3 golden verification

Current status: M0 paper/hardware golden revision 3 and context revision 8 are
current. M1 compact CSR revision 3, M2 DMA/run-configuration ingress, M3
context/control execution, M4 scratchpad/stream transport, M4.1 DMA preload,
M5 shared arithmetic, M6 homogeneous CGRA and M7 generated Phi, plus the non-production M1--M4
integration harness, passed
Vivado/XSim, property elaboration and OOC synthesis by 2026-08-25; this is not
a mathematical formal proof or full-design sign-off.

This directory verifies the reference chain independently of RTL maturity:

```text
primary papers
  -> models/v3/paper.py
  -> models/v3/hardware.py
  -> golden/*.paper.json.gz
  -> golden/*.hardware.json.gz
  -> observed RTL phase trace
```

Run the semantic and bit-accurate tests:

```powershell
py -3 -m unittest verification.v3.test_paper_golden verification.v3.test_hardware_golden -v
```

Generate or audit deterministic vectors:

```powershell
py -3 scripts/golden/generate_v3_phase_golden.py --suite smoke
py -3 scripts/golden/generate_v3_phase_golden.py --suite smoke --check
py -3 scripts/golden/generate_v3_phase_golden.py --suite scale
py -3 scripts/golden/generate_v3_phase_golden.py --suite scale --check
```

Compare an RTL-exported JSON/JSON.gz trace with the hardware golden:

```powershell
py -3 scripts/golden/compare_v3_phase_trace.py `
  --golden verification/v3/golden/m16_n24_k4_seed1.hardware.json.gz `
  --observed <rtl-trace.json.gz>
```

Comparison is exact and stops at the first differing phase/field. An LS result
may update outer algorithm state only after a passing `REFINEMENT_CERTIFICATE` and
`REFINEMENT_COMMIT`; `REFINEMENT_ROLLBACK` must leave the prior committed state unchanged.

## AXI4-Lite reconstruction control interface

Run the self-checking protocol/CSR simulation:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/sim/run_axilite_control.ps1
```

Elaborate embedded formal-intent properties with Vivado 2018.1:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/formal/check_axilite_control_properties.ps1
```

This gate checks property syntax/elaboration only. Vivado 2018.1 is not a formal
proof engine, so the result must not be reported as a bounded/unbounded proof.

## M2 DMA and run-configuration ingress

Run both self-checking M2 benches with all embedded assertions enabled:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/sim/run_m2.ps1 -EnableProperties
powershell -ExecutionPolicy Bypass -File scripts/formal/check_m2_properties.ps1
```

Coverage includes four-beat configuration fetch, every validation error class,
atomic commit, fixed-priority ownership, AXI read/write backpressure and error
injection, 4096-byte/256-beat boundary, oversized-request rejection and D18
sign-extension checks.

## M3 context/control execution

Run the compiler-generated context image and lifecycle benches, then compile
and elaborate every M3 formal-intent property:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/sim/run_m3.ps1
powershell -ExecutionPolicy Bypass -File scripts/sim/run_m3.ps1 -EnableProperties
powershell -ExecutionPolicy Bypass -File scripts/formal/check_m3_properties.ps1
```

Coverage includes ordered atomic image programming, explicit CFG-closure
finalization (target and fallthrough edges), one-time launch-entry bounds,
fixed one-cycle/four-port memory-configuration reads, reservation legality,
exact PC/loop/branch/wait trace, elastic stall, safe abort, missing/corrupt
image handling and run-controller terminal ownership. Expected trace is generated by
`compiler/v3/m3_control_image.py`; the testbench does not hand-code a second
control program. Detailed evidence is in
`reports/v3/M3_CONTEXT_CONTROL_STATUS.md`.
