# CSR v4

## Hiện hành: wrapper AXI-Lite và CPU registers

RTL `csr_top` nối AXI4-Lite 32-bit/4 KiB với `recovery_engine` qua
`host_command_bridge`: nạp image/Phi/vector, START/CANCEL, DONE/IRQ, đọc result và
metadata đều qua MMIO. [Register map](docs/v4/architecture/AXI_REGISTER_MAP.md),
[CPU status](docs/v4/architecture/CPU_INTERFACE_STATUS.md),
[IP packaging](docs/v4/architecture/IP_PACKAGING.md) và
[bằng chứng riêng](reports/v4/axi_ip_20260910/README.md). Chưa có DMA/AXI-HP,
synth/impl hoặc board claim. Các mục tối ưu phía dưới là lịch sử trước wrapper.

## Hiện tại: chuỗi năm tối ưu QR resident đã cài source

Năm bước QR resident đã được cài vào source: QR prefix append, block ownership remap, FACTOR_PROJECT_UPDATE, SCALAR_INSERT và support block-winner/range transport. Closure giữ đúng hai mảng PE 4×4 (32 PE) và một vector pool dùng chung. Hai batch Vivado XSim active10 fixed8 M32/N64/K8 và M64/N256/K8 chạy outer thực tế 8, với kết quả/raw trace/counter/quality diagnostic được validator paired kiểm.

Dùng profile tối ưu một cách explicit: `--qr-profile compact --target-kernel-revision 6`; compatibility default vẫn `balanced`. Xem [five-step evidence](reports/v4/five_optimizations_20260910/README.md), [A/B/C comparison](reports/v4/resident_chain_comparison_20260910/resident_chain_comparison_vi.md), [scalar RTL gate](reports/v4/scalar_insert_rtl_20260910/qualification.json), [numerical archive](reports/v4/scalar_insert_numerical_20260910/archive_manifest.json), và [installation manifest](reports/v4/scalar_insert_promotion_20260910/before_after_manifest.json).

Đây không thêm AXI/MMIO/DMA hay CPU register map; RF32×64 là state nội bộ của sequencer. Không có synthesis, timing, PPA, board hay production-bit claim. Fixed8 quality là diagnostic; một số float SNR vẫn dưới 20 dB nên không phải application-quality pass.

stream kernel with two 4×4 PE arrays. The [older baseline](docs/v4/architecture/BASELINE.md)
records the LSQR reference; it no longer selects the production solver.

The native streaming integration now connects loaded programs with branches
and subroutines, independent PE templates, live Phi/B, shared vector RAM and

plus six matched MP/GP/IHT cases. A separate [maximum-N gate](reports/v4/pipeline_max_program_comparison_20260909/README.md)
passes MP/GP/IHT/FISTA at M128/N1024/K2 and two outer iterations.
The [qualified shared pipeline](docs/v4/architecture/OPERATOR_PIPELINE.md) is now in live RTL.
Sparse forward for MP/GP/IHT is enabled explicitly with `sparse_forward=True`.

[Householder QR calibration](reports/v4/QR_NUMERICAL.md) passes 583 support
observations and 31 actual greedy application cases, with minimum SNR 21.622 dB.
No LSQR fallback. Candidate bits remain subject to held-out and RTL checks.

The existing LSQR integration connects the support builder, scalar RF/service, generic
32-PE kernels and stored-X certificate to transactional result publication.
Its unified regression was stopped for architecture review; no new full PASS.
Performance comparisons cover every one of the eleven small algorithm cases;
all improve with the shared transport change. Larger QR support qualification,
full application workloads and ZCU106 host integration remain open. Candidate
bit widths are unchanged; calibration is not held-out qualification.

The earlier Vivado 2018.1 baseline: **210 tests PASS**, zero failures/errors/skips,
204 stable source hashes, and all 42 pre-existing RTL/header/TB files unchanged.

`v4` is a directory/version label; RTL uses functional identifiers and `CSR_*`
macros. v2/v3 work remains separate. RTL tests use Vivado
`xvlog → xelab → xsim`, with Python stimulus and independent integer oracles.

Use [project guide](docs/v4/PROJECT_GUIDE.md) for the available Python runtime
if the `py -3` launcher is unavailable. The separate full reference regression
is `scripts/v4/run_rtl.py`; its interrupted run is not new acceptance evidence.
