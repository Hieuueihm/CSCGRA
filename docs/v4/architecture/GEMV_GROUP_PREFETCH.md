# GEMV output-group prefetch — implementation contract

Status: two focused Vivado XSim gates passed: parameter on/off plus future-response fault/cancel/reset/recovery. [The source archive](../../../reports/v4/context_stream_gemv_rtl_20260910/README.md) reports every case, including two small regressions under the TB backpressure schedule. Whole-program acceptance is separate.

The current command uses32 PEs: R1 computes32 outputs per group, R4 computes8 outputs with four reduction lanes each. Existing four-frame feeder, two matrix credits and command-local vector/tile caches remain the transport storage. In the M64/N256 fixed8 FISTA baseline, forward and transpose each accept512 frames, but service cycles are551 and975 respectively. This motivates hiding boundary restart latency; it does not imply all extra cycles are idle.

Separate issued coordinates from active compute/write coordinates. issue_out, issue_red, issue_step advance only on accepted feeder requests; after a group's last frame, allocation can advance to the next output group. The all-issued flag asserts only after the last frame of the entire command. Existing four slots bound speculation; no PE work or destination publication is speculative.

Active gemv_out remains fixed through terminal reduction, rounding, fault validation and scratch write. delivery_group_done is set on acceptance of the current group's last frame. It gates both feeder consumption and feeder_bad response validation until the next group's launch/reset, so a prefetched future response cannot be mistaken for a malformed current-group frame. delivered_frame and feeder serial remain command-global; delivered_red/step reset at the established group handoff.

Existing ACC lifetime remains: final frame -> pipeline drain -> fixed registered reduction/rounding -> validated DONE -> scratch write -> next LAUNCH/ACC reset. Prefetch may overlap data reads only. Queue payload, masks and tags must hold on stalls. Cancel, reset or current/future-group fault flushes the queue through the existing cancellation path; final public publication remains command-atomic. Host writes remain disabled while busy. Current operand validity checks cover the whole source before allocation begins.

Required XSim comparison: R1/R4 forward/transpose, dense and Phi, odd rows/columns/reductions, single-frame groups, queue crossing multiple small groups, metadata/memory faults, backpressure, reset/cancel during terminal and prefetched responses. Compare raw vectors and numeric fault behavior, accepted frame count, group count and source identity; measure full GEMV service cycles and all10 whole-program job cycles. Do not promote a local bubble change with no command-level benefit. No new matrix/vector copy or PE; resource/timing/board claims require later implementation evidence.
